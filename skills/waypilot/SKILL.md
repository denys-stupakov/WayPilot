# WayPilot — рабочий контекст проекта

WayPilot строит и **сравнивает два маршрута** между остановками пользователя по дорогам Словакии.
Backend один раз при старте строит граф из OSM-данных, а на каждый запрос гоняет по нему A* с выбранным профилем и стримит результат в браузер через Server-Sent Events.

Полная карта проекта — в `PROJECT_MAP.md` в корне репозитория. Этот файл — про **инструменты, проблемы и решения**.

## Быстрая ориентация по коду

- Точка входа backend — `backend/server.js` (эндпоинт `GET /route-stream`, SSE).
- Ядро маршрутизации — `backend/algorithms/astar.js` (A* + все профили в объекте `PROFILES`).
- Построение графа — `backend/getRoads.js` (парсинг + теги) → `backend/buildGraph.js` (рёбра).
- Структуры — `Graph.js` (adj + edgeMap), `nodes.js` (узлы, светофоры, `mergeRoads`), `MinHeap.js`.
- Точка входа frontend — `frontend/src/OSMRoads.jsx` (состояние, SSE-клиент, карта Leaflet).

## Инструменты и почему они выбраны

| Инструмент | Роль в проекте | Почему именно он |
|-----------|----------------|-------------------|
| **Собственный A*** (`astar.js`) | Прокладка маршрута по графу | Нужны кастомные функции стоимости под каждый профиль (грузовики, светофоры, покрытие) — готовые роутеры это не дают гибко |
| **MinHeap** (`MinHeap.js`) | Приоритетная очередь A* с `updatePriority` | O(log n) на обновление приоритета вместо линейного поиска; хранит `nodePosition` для быстрой переиндексации |
| **kd-дерево** (`kdt`) | Привязка клика пользователя к ближайшему узлу дороги | Тысячи узлов; линейный перебор на каждый клик недопустим. Лимит привязки — 5 км (`MAX_DISTANCE_METERS`) |
| **Server-Sent Events** | Стриминг двух маршрутов в браузер | Первый маршрут появляется, пока считается второй; проще WebSocket для однонаправленного потока |
| **fastHaversine** | Расстояние между координатами (м) | Дешёвая метрика; используется и в весах рёбер, и в допустимой эвристике A* |
| **mergeRoads** (`nodes.js`) | Склейка последовательных сегментов дорог | Меньше рёбер в графе → быстрее A* |
| **Leaflet + react-leaflet** | Карта и отрисовка Polyline | Бесплатные OSM-тайлы, простая работа с гео-полилиниями |
| **@dnd-kit / @hello-pangea/dnd** | Переупорядочивание остановок мышью | Доступный drag-and-drop без ручной возни с событиями |
| **Docker Compose** | Запуск backend :3001 + frontend :5173 | Единый воспроизводимый старт обоих сервисов |

## Решённые проблемы и как они решены

### 1. Клик пользователя не попадает точно в дорогу
Пользователь кликает по произвольной точке карты, а маршрут должен идти по существующим дорогам.
**Решение:** kd-дерево по «важным» узлам + `findNearest`, которое «примагничивает» точку к ближайшему узлу и возвращает `snapped`-координаты. Если ближе 5 км дороги нет — сегмент помечается ошибкой `invalid_stop`.

### 2. Один A* на пять разных запросов оптимизации
Нужны «самый короткий», «самый быстрый», «объезд светофоров», «по качеству покрытия», «для грузовиков».
**Решение:** единый `astar()`, а различия вынесены в объект `PROFILES` — каждая запись даёт `cost`, `heuristic` и опционально `canTraverse`. Добавить новый режим = добавить запись в `PROFILES` + `<option>` в `CompareRoutes.jsx`.

### 3. Маршрут для грузовика может не существовать
Если по массе/запрету `hgv` пути нет, пустой ответ не объясняет причину.
**Решение:** при провале A* с профилем `hgv` вызывается `findMaxCapacityPath` (модифицированный обход «максимальной ёмкости»), который сообщает, какая максимальная масса вообще проходит (`... maximálna možná kapacita je X t`).

### 4. Ограничение по массе ТС
**Решение:** фильтр `canTraverse` в профилях `weight` и `hgv` отбрасывает рёбра с `hgv === "no"` и рёбра, где `vehicleWeight > maxweight`, ещё на этапе обхода соседей.

### 5. Второй маршрут «залипал» за первым в SSE
Оба события уходили в один тик, буфер не сбрасывался.
**Решение:** `await new Promise(r => setImmediate(r))` между отправкой `route1` и `route2` — даёт Node сбросить буфер, маршруты приходят по отдельности.

### 6. Слишком большой граф
Каждая точка геометрии дороги как вершина = гигантский граф.
**Решение:** вершинами графа становятся только «важные» узлы (концы дорог, перекрёстки со степенью > 1, светофоры). Промежуточная геометрия хранится в `pathSegments` и подставляется только при отрисовке (`smoothPathCoords`). Плюс `mergeRoads` склеивает однотипные сегменты.

### 7. Неполные данные OSM
У части дорог нет `maxspeed`, `lanes` и т.п.
**Решение:** таблица `roadDefaultTags` в `getRoads.js` задаёт дефолты по типу дороги (`highway`); при отсутствии тега берётся значение по умолчанию.

### 8. Реалистичное время в пути
Длины ребра мало — светофоры добавляют задержку.
**Решение:** `TRAFFIC_LIGHT_WAIT_TIMES` по типу дороги; при реконструкции пути и в профиле `avoidTrafficLights` добавляется задержка на узлах-светофорах (`hasTrafficLight`).

### 9. Docker / прокси / окружение (по git-истории)
Серия фиксов: адреса прокси Vite и обращение к backend по имени сервиса в Docker-сети, вынос API-URL в `VITE_API_URL` (`.env` в `.gitignore`), переход на `node:24-alpine`, копирование файлов в Dockerfile.
**Решение:** фронтенд ходит на `import.meta.env.VITE_API_URL`, а не на захардкоженный localhost; сервисы общаются по именам из `docker-compose.yml`.

### 10. Падение UI при кривом ответе
**Решение:** `ErrorBoundary` оборачивает всё приложение; `handleRouteUpdate` проверяет наличие `smoothPathCoords` перед отрисовкой.

### 11. Невалидные дефолты профиля роняли SSE-запрос
`server.js` по умолчанию использовал `mode1="normal"` и `mode2="trafficLights"` — таких ключей в `PROFILES` нет, `astar` бросал `Unknown routing profile`, а обработчик `/route-stream` не имел try/catch → поток зависал без события ошибки.
**Решение:** дефолты заменены на реальные ключи (`shortest`, `avoidTrafficLights`) и в `server.js`, и в начальном состоянии `mode2` во фронтенде (`OSMRoads.jsx` — было `useState("trafficLights")`); всё тело `/route-stream` обёрнуто в try/catch; при любой ошибке клиенту уходит `event: error` с JSON `{ type, message }`, соединение корректно закрывается. Разбор `stops` тоже защищён отдельным try/catch.

### 12. Единый формат ошибок SSE
Раньше первая ошибка («Invalid stops») слалась как plain text, а клиент делал `JSON.parse` и падал в catch.
**Решение:** все error-эвенты теперь JSON `{ type, message, index? }`. На фронте (`OSMRoads.jsx`) обработчик различает `invalid_stop` и остальные типы, показывает `message`, а «пустой» error (обрыв соединения EventSource) игнорирует.

### 13. Стабильный id дороги
`getRoads.js` генерировал `id: Math.random()` (возможны коллизии, нестабильно между запусками).
**Решение:** инкрементный счётчик `roadIdCounter++`.

### 14. Тесты алгоритмов
**Решение:** добавлен каталог `backend/tests/` на встроенном `node:test` (без зависимостей). Запуск — `npm test` в `backend`. Покрыто: `fastHaversine`, `MinHeap` (вкл. decrease-key и стресс), `nodes`/`mergeRoads`, `buildGraph`, `astar` (кратчайший путь, все 5 UI-профилей, фильтр массы, `hgv=no`, светофор). **Держи тесты зелёными перед коммитом в backend.**
